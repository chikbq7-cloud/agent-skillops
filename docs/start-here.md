# 从零开始读这个项目

## 你现在首先做什么

先在页面跑一次“代码审查样例”，不用准备 Key，也不用先理解 Google ADK。保存并确认评测集，启动任务，展开一份 train 报告，再展开一份 holdout 报告，找到 `input / output / criterion / status / reason` 五个字段。

然后跑“安全拒绝样例”。你的第一份学习记录应回答：为什么功能分数提高了，系统仍没有保留这次改动？答案在该候选的安全报告，不在模型自我评价里。

## 先建立五个概念

- Skill：任务说明书，如“如何审查 Python 代码”，不是模型权重。
- Case：一次具体考试题，如审查一个除法函数。
- Criterion：判题标准，如建议是否具体、是否泄漏保密标记。
- Version：某份 `SKILL.md` 和引用文件的完整快照。
- Job：一次优化任务，包括多个候选版本、多个评测 Run 和最后的发布决定。

`Session/Workspace` 是前端本次操作的业务 ID，不等于 Google ADK 的模型对话 Session。

## 六天学习路线（建议）

| 天数 | 阅读位置 | 动手练习 | 你要讲清楚 |
| --- | --- | --- | --- |
| 1 | `backend/examples.py`、`domain.py` | 导出 JSON，改单个检查再导入 | 场景与标准怎么绑定；为什么不通用套题 |
| 2 | `evaluation.py` | 写一个 JSON Schema 检查；运行测试 | 不同评分器如何组合；漏项为何算 error |
| 3 | `adk_optimizer.py` | 用断点看 Analyst 的输入 | Agent 不会自动互相聊天，信息由函数传递 |
| 4 | `jobs.py` | 对照每个 Run 的版本 ID 和 split | train 用于优化，holdout 只在最后检验 |
| 5 | `store.py`、`app.py` | 发布、重启、查看指针；运行回滚测试 | 版本快照、发布指针、原子事务 |
| 6 | `frontend/src/app/page.tsx`、测试目录 | 断开后端观察提示；设预算为 1 | SSE 为什么要轮询兜底；预算为何包含重试 |

先读自己看得懂的主路径，不需要一开始读 ADK 框架源码。随后再看 `Agents.real()` 中 Runner、Session、Event 的关系。

## 和上游对比

GitHub 开发分支先保留“导入上游基线”的独立提交，再提交新增能力。原工作目录不参与修改，所有工作在 `feature/skillops-core` 的独立工作树中。

你可以在 GitHub 的 PR 中查看：删除内存 sessions 字典、把评分拆成独立模块、把一次运行拆成任务/版本/报告、增加发布检查，以及前端从临时向导变成历史工作台。

## 最后写一份自己的复盘

不要直接背本项目文档。自己用三段话解释：原来有什么问题；你选择了什么最小设计；测试如何证明边界生效。每一段都带一个具体函数和一个失败案例。

简历现阶段可写“基于开源项目二次开发 Skill 优化与发布治理工作台，实现固定评测、独立评分、回归/安全门禁、版本审计与任务控制”。只有真实实验完成后才写准确的效果数值，不写离线模拟提升、不写企业真实上线。
