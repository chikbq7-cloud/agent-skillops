# 下一步：把流程验证变成真实项目证据

## 当前已经能证明什么

离线用例可以证明输入校验、版本追溯、评分完整性、任务限制、安全/回归门禁、发布资格等工程约束。**不能**证明 Gemini 输出更好，也不能证明任何企业上线效果。

## 真实实验怎么做

1. 只选一个你理解的文本 Skill，例如 Python 代码审查。确认没有隐含脚本、外部 API 或工具执行需求。
2. 自己准备至少 20 个训练输入、10 个独立保留输入；覆盖正常、边界、拒绝场景，不用模型自动生成的漂亮分数当结论。系统硬性最低值 5/3 只是体验起点。
3. 生成评测草稿后逐题审查：把“回答要好”改成能举例判定的 pass/fail 条件。配置确定性格式规则与安全规则，将不可退化的功能标记 critical。
4. 在真实模型模式用同一冻结 Suite 比较基线和候选。记录模型名、Suite hash、版本 ID、采样参数、日期、请求数、Token 数、延迟、每项失败证据。
5. 人工独立标注部分输出，与 Judge 对比。分歧样例要复盘，不能只挑模型判得正确的例子。优先改标准，而不是为了分数删坏题。
6. 优化结束再查看 holdout，不能把保留题失败原文回填给 Analyst 然后仍宣称它是独立保留集。下一轮实验准备新的未见输入。
7. 做一个消融对照：有无规则检查；只总分 versus 完整失败证据；有无发布门禁。每次只改一个变量，预算不足就缩小实验，不编造数值。

## 简历写法（先不要填效果数字）

“Agent SkillOps：基于开源 ADK Skill 优化项目进行二次开发，负责固定评测与发布治理，使用 FastAPI、SQLModel/SQLite 实现版本持久化，构建规则检查 + 独立 Judge 的证据链与 train/holdout 隔离，增加安全/回归门禁、人工发布回滚、任务预算与 SSE 进度恢复。”

如果面试官问你做了什么，展示基线提交与功能提交的差异、一个漏评分被阻断的测试、一个安全退化被拒绝的 Run，以及你自己完成的真实实验。不要宣称独立开发整个上游项目。
